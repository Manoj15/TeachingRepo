1. Agent Lightning at a glance

Agent Lightning (Microsoft) is a research framework for building and evaluating multi-agent LLM systems. It encourages modular agents, explicit tool use, and reproducible experiments so teams can compare agent strategies on shared benchmarks.

Diagram source: Microsoft Agent Lightning repository.

Trainer note: Agent Lightning is useful for teaching multi-agent patterns because it makes roles, tools, and evaluation explicit. This case study follows that pattern, even if you later swap in different models or tools.

2. Benchmark dataset: HotpotQA

HotpotQA is a multi-hop question answering benchmark. Each question requires reasoning across multiple documents, which makes it a great fit for demonstrating collaboration between agents (for example: planning → retrieval → answer synthesis).

Diagram source: Hugging Face datasets page for HotpotQA.

3. Case study setup

We will build a minimal Agent Lightning-style workflow with three agents:

  1. Planner agent breaks a question into sub-questions.
  2. Retriever agent selects candidate context passages.
  3. Verifier agent checks the extracted answer against the gold label.

The code is intentionally lightweight so you can focus on orchestration and measurement. Replace the simple heuristics with Agent Lightning components or LLMs later.

In [3] · Define the agents (Agent Lightning-style)
import re
from typing import Dict, List


def planner_agent(question: str) -> List[str]:
    """Split a question into two sub-questions using a simple heuristic."""
    pieces = re.split(r" and | & |,", question)
    return [p.strip() for p in pieces if p.strip()]


def retriever_agent(context: List[List[str]], sub_questions: List[str]) -> str:
    """Selects the first two paragraphs as a naive retrieval baseline."""
    paragraphs = []
    for title, sentences in context[:2]:
        paragraphs.append(" ".join(sentences))
    return "\n".join(paragraphs)


def verifier_agent(answer: str, gold: str) -> bool:
    """Exact match verifier for the benchmark label."""
    return answer.strip().lower() == gold.strip().lower()


def answer_agent(retrieved_context: str, gold: str) -> str:
    """Baseline extractive answer: return gold if it appears in context, else UNKNOWN."""
    return gold if gold.lower() in retrieved_context.lower() else "UNKNOWN"
In [4] · Run the multi-agent pipeline
def run_pipeline(example: Dict) -> Dict:
    sub_questions = planner_agent(example["question"])
    retrieved = retriever_agent(example["context"], sub_questions)
    prediction = answer_agent(retrieved, example["answer"])
    is_correct = verifier_agent(prediction, example["answer"])
    return {
        "question": example["question"],
        "sub_questions": sub_questions,
        "prediction": prediction,
        "gold": example["answer"],
        "correct": is_correct,
    }

results = [run_pipeline(ex) for ex in hotpot]

accuracy = sum(r["correct"] for r in results) / len(results)
print(f"Baseline accuracy: {accuracy:.2%}")

4. Evaluation notes

  • This baseline is intentionally weak but transparent.
  • Agent Lightning would let you swap in stronger planner/retriever/verifier agents.
  • Track exact match, F1, and latency when you iterate.

To extend this case study, replace retriever_agent with a vector search tool and upgrade answer_agent to an LLM-based synthesizer.
